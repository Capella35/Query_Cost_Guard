### Bug found: GROUP BY columns lose their table

`sql_ast.group_by_columns` returns bare column names (`u.id` → `id`), and the Guard then checks the GROUP BY cardinality rule on **every** table in the query that has a column of that name. In B18 and B19, `GROUP BY u.id` (users) was reported as "near-unique column 'id' in 'events'". In B19 that wrong finding is the only reason the query was flagged; without it B19 would have been allowed. The bug is not BigQuery-specific (it predates this eval and affects DuckDB the same way). Not fixed here.
